\section{Methodology}
\label{sec:methodology}

The design is recorded in full in the project's methodology
note~\cite{pwnzzdocsmeth}; bring-up and replay instructions are in the
reproduction and manual-testing
guides~\cite{pwnzzdocsrepro,pwnzzdocsmanual}.

\subsection{Target, Pinning, and the Unit of Measurement}
\label{sec:method:target}

All measurements were taken against PwnzzAI Shop pinned at application
commit \code{cd3ac0d1} and container image digest
\code{sha256:7878fbd7\ldots}, published on
\code{127.\bk 0.\bk 0.\bk 1:18080} only and reaching an inference
backend on the host. The model is \code{llama3.2:1b}, selected by the
deployment configuration rather than for its capability. That is a
methodological constraint and should be read as one: a 1B model
refuses, rambles, or drifts off-task more often than a frontier model,
suppressing absolute attack success rates across the board. This study
therefore treats \emph{relative} differences --- between persona
levels, guardrail layers, a mitigation on and off, or two detectors
judging the same output --- as the interpretable signal, and absolute
rates as lower bounds specific to this deployment. Mutable application
state (uploads, the RAG corpus, the instance database) is mounted from
a directory that can be deleted to restore a known baseline; the
application re-seeds its catalogue, accounts, and routing flags on
first request after a fresh start.

A \emph{task} is one Garak invocation: a single probe posed to a single
generator under a specific configuration; a \emph{suite} is an ordered
list of tasks answering one assessment question. The runner writes a
per-task JSON configuration and calls \code{garak.\bk cli.\bk main} with
it --- the entry point a human operator would use --- so Garak owns
prompt sequencing, generation, detector execution, scoring and artefact
production, and the runner decides only \emph{what} runs and
\emph{where} the output lands. Each task emits \code{report.jsonl}
(every attempt with prompts, outputs, per-detector scores and notes),
\code{report.html}, \code{hitlog.jsonl} when hits exist, and the exact
\code{config.json} used; a per-suite manifest ties the tasks to the
target fingerprint, and the retained configurations are executable
reproduction instructions.

One implementation detail is load-bearing for every sweep. Garak caches
plugin instances keyed by the string form of the configuration root,
and because all tasks in a suite share one global configuration object
in one process, that key is identical across tasks; without
intervention the second task would silently reuse the first task's
generator, and a five-level persona sweep would execute level~1 five
times. The runner clears the instance cache before each task --- the
difference between a genuine sweep and the same run repeated $N$ times,
and why the trends in Sec.~\ref{sec:results} can be attributed to the
swept parameter.

Prompt corpora are deliberately compact and legible rather than large.
Each probe carries five to twelve prompts, and every prompt exercises
one identifiable technique --- direct request, instruction override,
authority claim, emotional framing, fictional framing, indirection,
encoding, obfuscated read-back, paraphrase, hypothetical. Because each
prompt has a known intent, per-prompt outcomes read as a
technique-level result rather than as noise in an aggregate. Coverage
breadth is traded for attributability.

Four controls are built into the design rather than applied post hoc.
\textbf{A paired clean control for poisoning:} the sentiment surface
fits two models per run --- one on the baseline corpus, one on baseline
plus poison --- and classifies every evaluation prompt with both, so
success is \emph{disagreement} between them; a phrase the classifier
always misclassified would otherwise count as a success. Both fits are
deterministic, so the control is exact. \textbf{Mitigation on/off for
retrieval poisoning:} the identical poison document and prompt set are
run twice, with trusted-only retrieval disabled and then enabled.
\textbf{A delivery-integrity check for indirect injection:} the QR
generator records whether the payload round-tripped through the decode
step, since a mangled payload means the target was never asked the
intended question; a diagnostic detector marks such attempts for
exclusion rather than letting them count as defended. \textbf{Negative
and benign prompts:} the poisoning probe carries no-trigger controls,
so general degradation of the classifier --- a broader failure than a
targeted backdoor --- is separable.

\subsection{Metrics}
\label{sec:method:metrics}

For each \emph{(probe, detector)} pair Garak reports counts of
\code{passed}, \code{fails} and \code{nones}. The headline metric is
attack success rate over \emph{evaluated} attempts,
$\mathrm{ASR} = \mathit{fails} / (\mathit{passed} + \mathit{fails})$,
with \code{nones} excluded from the denominator by construction. With
the abstention rules of Sec.~\ref{sec:arch:detectors}, a transport
failure, a missing ground truth or an unfitted control model reduces
the sample size rather than silently entering the numerator or
denominator. In these runs the abstention count was zero for every
detector, so all 678 attempts were evaluated; the mechanism is
nonetheless load-bearing, because it lets a partial failure be
recognised instead of absorbed into a rate.

Roll-ups by attack family and by OWASP LLM Top~10 (2025)
category\footnote{\url{https://genai.owasp.org/llm-top-10/}. Used as a
reporting frame so findings land in vocabulary an operations team
already has; no coverage of the list is claimed.} use each probe's
declared \emph{primary} detector. Extended detectors --- including a
stock Garak detector on every applicable probe --- are reported
alongside rather than merged, since merging would destroy exactly the
comparison this study is interested in. Scores are thresholded at
$0.5$, which makes two graded detectors consequential:
\code{CustomerPII} assigns $0.5$ to a lone email address, since a model
can invent a plausible address without retrieving one, and
\code{Poisoned\bk Retrieval\bk Influence} assigns $0.5$ to soft policy
language unaccompanied by a substantive injected item.

\subsection{Reproducibility, Provenance, and their Limits}
\label{sec:method:repro}

Garak's RNG is seeded, fixing prompt sampling and buff ordering;
parallelism is disabled everywhere; the image is pinned by digest; and
the ground-truth constants are re-validated against the pinned source
by contract tests on every run of the test suite. The full 28-task set
completes in roughly 15 minutes of wall-clock time, dominated by model
inference. What is \emph{not} reproducible bit-for-bit is the language
model behind the HTTP path, which is not seedable through the
application's interface, so individual generations vary between
executions. That is why every LLM-backed task runs multiple
generations, why the analysis reports rates rather than single
outcomes, and why Sec.~\ref{sec:results} interprets ordering and
magnitude of differences rather than individual figures. The
sentiment-poisoning surface is exempt: it involves no language model,
and its numbers reproduce exactly.
