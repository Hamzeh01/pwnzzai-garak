\section{Architecture}
\label{sec:architecture}

This section condenses the design recorded in the project's architecture
note~\cite{pwnzzdocsarch}; the per-scenario catalogue it summarises is
generated from the plugins themselves~\cite{pwnzzdocsscen}.

\subsection{Design Position: the Application is the Target}
\label{sec:arch:position}

The system under assessment is not a language model but a web
application that embeds one. PwnzzAI Shop is a Flask application of some
seventy routes in which the LLM is reached only through application
code: an input filter runs before generation, a retrieval step assembles
context, an output filter rewrites the response, a QR decoder converts
an uploaded image into prompt text, and an agentic SQL tool executes
model-authored queries. Its security-relevant failures are properties of
that pipeline, not of the model in isolation.

The assessment is therefore built on Garak, and specifically on Garak's
decision that a \emph{generator} need not be a model --- it may be any
dialogue system exposing a text-in/text-out interface. Wrapping each HTTP surface as a generator makes the
application the object under test while leaving Garak's harness,
scheduling, scoring, and reporting untouched
(Fig.~\ref{fig:architecture}).

\subsection{Plugin Registration Without Installation}
\label{sec:arch:registration}

Garak resolves a specification such as
\code{probes.\bk pwnzz.\bk Coupon\bk Extraction} two ways: by importing
\code{garak.\bk probes.\bk pwnzz}, and by consulting an in-memory plugin
cache that backs \code{enumerate\_\bk plugins} and hence the CLI parser.
A registration step (\code{garak\_\bk pwnzz.\bk bootstrap}) satisfies both
at run time: it appends the project's plugin directories to the
corresponding \code{garak.\{probes,\bk generators,\bk detectors\}.\_\_path\_\_}
lists so imports resolve with ordinary Python semantics, and inserts the
plugin classes into Garak's cache so they are enumerable and nameable on
the command line. No files are copied into the Garak installation and no
stateful install step exists, yet the contributed plugins behave exactly
as built-in ones --- so any task replays with the stock entry point
after a single import of the bootstrap module.

\subsection{Generators: One Class per Application Surface}
\label{sec:arch:generators}

Nine generators cover the surfaces reachable in this deployment, under a
deliberately conservative rule: a custom generator is written \emph{only}
where the transport is not plain text-in/text-out, or where run state
must be established before the surface can be queried. Plain JSON chat
endpoints need no new code --- Garak's stock \code{RestGenerator} with a
configuration file reaches them, and the study retains one such
configuration as a working demonstration of that path
(Table~\ref{tab:generators}).

Four invariants hold across all generators and are enforced by the test
suite. \textbf{Absence of a response is not a defended attack:} a
transport error or unexpected HTTP status returns \code{None}, which
propagates to the detectors and is accumulated under \code{nones},
excluded from the denominator, so a broken call can never inflate the
measured pass rate. \textbf{Retries are disabled}, because a retried
attack against a non-deterministic system is a \emph{different} attempt;
repetition is requested through Garak's \code{generations} parameter,
which keeps every repeat visible as its own row. \textbf{Stateful
surfaces run single-threaded}, since several generators hold run state
--- a poisoned corpus, a fitted weight vector, an authenticated session
--- that parallel execution would interleave, destroying the attribution
of an effect to a configuration. \textbf{The target is loopback-bound in
code:} a guard rejects any non-loopback host, any non-HTTP scheme, and
any URL carrying credentials, a query, or a fragment, so the suite
cannot be pointed at a third party.

\subsection{The Notes Side-Channel}
\label{sec:arch:notes}

An application's structured response carries far more than the text the
model produced: the escalation stage's narrative, the retrieved
passages, internal leak flags, the generated SQL, the classifier's score
and confidence, the HTTP status, the latency. Garak's
\code{Message.\bk notes} field provides a per-response dictionary that
survives into \code{report.jsonl}, and every generator populates it.
This is what makes ground-truth detection possible without out-of-band
configuration: the generator knows which secret is in play for the level
or stage it was configured with and records it alongside the response,
so a detector reads the ground truth from the response it is judging ---
which keeps scoring correct even when a suite sweeps levels within a
single process (Fig.~\ref{fig:lifecycle}).

\subsection{Detectors: Ground Truth Instead of Signature}
\label{sec:arch:detectors}

Automatic failure detection is the hard part of LLM security testing,
because whether an output constitutes a failure depends on the deploying
organisation's intent rather than on any property of the text. PwnzzAI
admits a sharper question than a generic detector can ask, because its
policy is legible from its source: the system prompts
name the exact word that must not be emitted at each level; the
disclosure lab synthesises PII of exactly specified shapes; each seeded
account owns an unguessable routing flag in an isolated database. Every
such constant is transcribed into a single module and re-verified
against the pinned source by contract tests that fail if any value
drifts. Twelve detectors (Table~\ref{tab:detectors}) therefore test a
\emph{specific policy violation against ground truth} rather than a
stylistic signature~\cite{pwnzzdocsmeth}.

Two refinements are the substance of the architectural claim.
\emph{Obfuscation-aware leak detection:} at the two output-filter stages
the application string-replaces the exact secret on the way out, so a
detector matching only the literal string would score a complying model
as clean. \code{CouponLeak} therefore also matches leetspeak,
separator-injected, and whitespace-stripped forms, and records
\emph{which} rendering matched, so the analysis can distinguish ``the
model said the word'' from ``the model routed around the filter''.
\emph{Abstention over false assurance:} every detector returns
\code{None}, never $0.0$, when it cannot judge; scoring $0.0$ for
\code{CouponLeak} with no secret in the notes would assert ``no leak''
on evidence that says nothing at all. Combined with the generator-side
rule, the denominator of every reported rate contains only attempts
actually evaluated.

\subsection{An LLM-as-a-Judge as an Opt-In Second Opinion}
\label{sec:arch:judge}

Ground-truth detection has one blind spot: a response can satisfy the
attacker's goal \emph{without matching the pattern} --- a paraphrase, a
hint that gives the coupon away without saying it, a refusal that leaks
while declining. \code{CouponLeak} scores all of those $0.0$, correctly
by its own definition and wrongly by the attacker's. The suite's most
recent addition closes that gap with a judge model registered as an
ordinary Garak detector, so judged runs produce the same artefacts as
every other run. It is deliberately constrained: \textbf{off by
default}, since it costs a model call per generation and, unlike the
ground-truth detectors, can be wrong; \textbf{never primary}, because
its value is the \emph{disagreement} with the ground-truth verdict
rather than its raw counts; driven by \textbf{per-scenario criteria},
since asked the generic question a small judge grades on tone and reads
a polite refusal as failure; and returning \textbf{\code{None}, not
$0.0$}, for an empty response, an unreachable judge, or an
\code{ambiguous} verdict.

The judge is itself a target: it reads attacker-controlled text and
attacker-influenced output from a corpus that is a prompt-injection
corpus by construction --- the same exposure Greshake et al.\ describe
when untrusted retrieved content reaches a model that will act on
it~\cite[Sec.~3]{greshake2023}, one step further down the pipeline. Two
mitigations, neither sufficient alone:
the system prompt states that an embedded instruction is \emph{evidence
of a successful attack} rather than something to obey; and every
untrusted field is fenced in a named delimiter, so the judge can tell
where attacker text starts and stops even when that text imitates a
system message.

One design decision was measured rather than assumed, and it is why a 1B
judge is usable at all. Small judges fail in a specific, silent way:
they answer the same label to everything and invent reasoning to match,
producing a table of confident-looking verdicts with no information in
it. Asked for \code{\{verdict, reasoning\}}, \code{llama3.2:1b} returned
``success'' for plain refusals, with reasoning claiming the response
revealed the coupon word in plain text. Because Ollama's constrained
decoding follows the schema's property order, making the verdict the
model's \emph{last} field forces it to copy a verbatim span out of the
response \emph{before} it reasons or decides --- and it cannot quote a
coupon word from a refusal. Table~\ref{tab:judge} reports the effect on
a stratified 46-attempt sample drawn from the study's own attempts, up
to three hits and three misses per probe, graded against the
ground-truth detectors. The quoted span is reported rather than
discarded, which makes a judge hit auditable.

The resulting judge is high-precision and low-recall: about $75\,\%$ of
what it calls a success is real, and it misses roughly half the real
hits. For a second opinion that is the useful profile --- a ``success''
on an attempt the pattern detector scored $0.0$ points at a real missed
leak, and the misses cost nothing because the ground-truth detector
already covers them --- but it does not support quoting the judge's own
attack success rate as a headline number, and this study does not. Two
further guards are reported rather than assumed: the judge defaults to
the model the lab already pulled, which makes it share weights with the
model under assessment, a known soft-grading bias recorded in the run
manifest; and a judge returning one label for $\ge 95\,\%$ of attempts
is flagged as unusable rather than having its counts reported. Because
the judge is opt-in and calibrated only against a 1B grader, no number
elsewhere in this paper depends on it.

\subsection{Verifying the Application's Own Oracle, and Aggregating}
\label{sec:arch:oracle}

Three surfaces ship their own leak flag --- \code{has\_leakage} on the
comment RAG, \code{has\_\bk access\_\bk violation} on the order assistant,
\code{unsafe\_\bk hint\_\bk in\_\bk answer} on the catering RAG --- and none
scores anything. They travel in the notes, and the analysis layer
cross-tabulates them against the independent detector attempt by
attempt: agreement corroborates a finding, and disagreement is itself a
reported result about whether an application-supplied signal can be
trusted. That layer reads \code{report.jsonl} back into records and
aggregates but never re-judges an outcome, so all pass/fail/none counts
originate from Garak's own evaluation entries and every derived table
regenerates from the retained raw artefacts without the analysis quietly
changing a verdict.
