\section{Architecture}
\label{sec:architecture}

This section condenses the project's architecture
note~\cite{pwnzzdocsarch}; the per-scenario catalogue it summarises is
generated from the plugins themselves~\cite{pwnzzdocsscen}.

\subsection{Design Position, and Registration Without Installation}
\label{sec:arch:position}

PwnzzAI Shop is a Flask application of some seventy routes in which the
LLM is reached only through application code: an input filter before
generation, a retrieval step assembling context, an output filter
rewriting the response, a QR decoder turning an uploaded image into
prompt text, and an agentic SQL tool executing model-authored queries.
Its security-relevant failures are properties of that pipeline. The
assessment is therefore built on Garak's decision that a
\emph{generator} need not be a model --- it may be any dialogue system
exposing a text-in/text-out interface. Wrapping each HTTP surface as a
generator makes the application the object under test while leaving
Garak's harness, scheduling, scoring and reporting untouched
(Fig.~\ref{fig:architecture}).

Garak resolves a specification such as
\code{probes.\bk pwnzz.\bk Coupon\bk Extraction} two ways: by importing
\code{garak.\bk probes.\bk pwnzz}, and by consulting an in-memory plugin
cache that backs \code{enumerate\_\bk plugins} and hence the CLI parser.
A registration step (\code{garak\_\bk pwnzz.\bk bootstrap}) satisfies
both at run time, appending the project's plugin directories to the
corresponding
\code{garak.\{probes,\bk generators,\bk detectors\}.\_\_path\_\_} lists
and inserting the plugin classes into the cache. No files are copied
into the Garak installation and no stateful install step exists, yet
the plugins behave exactly as built-in ones, so any task replays with
the stock entry point after one import of the bootstrap module.

\subsection{Generators: One Class per Application Surface}
\label{sec:arch:generators}

Nine generators cover the surfaces reachable in this deployment, under
a conservative rule: a custom generator is written \emph{only} where
the transport is not plain text-in/text-out, or where run state must be
established before the surface can be queried
(Table~\ref{tab:generators}). Plain JSON chat endpoints need no new
code --- Garak's stock \code{RestGenerator} with a configuration file
reaches them, and the study retains one such configuration as a working
demonstration.

Four invariants hold across all generators and are enforced by the test
suite. \textbf{Absence of a response is not a defended attack:} a
transport error or unexpected HTTP status returns \code{None}, which is
accumulated under \code{nones} and excluded from the denominator, so a
broken call cannot inflate the pass rate. \textbf{Retries are
disabled}, because a retried attack against a non-deterministic system
is a \emph{different} attempt; repetition goes through Garak's
\code{generations} parameter, keeping every repeat visible as its own
row. \textbf{Stateful surfaces run single-threaded}, since several
generators hold run state --- a poisoned corpus, a fitted weight
vector, an authenticated session --- that parallel execution would
interleave, destroying the attribution of an effect to a configuration.
\textbf{The target is loopback-bound in code:} a guard rejects any
non-loopback host, non-HTTP scheme, or URL carrying credentials, a
query, or a fragment.

\subsection{The Notes Side-Channel, and Ground-Truth Detection}
\label{sec:arch:notes}

An application's structured response carries far more than the text the
model produced: the escalation stage's narrative, the retrieved
passages, internal leak flags, the generated SQL, the classifier's
score and confidence, the HTTP status, the latency. Garak's
\code{Message.\bk notes} field provides a per-response dictionary that
survives into \code{report.jsonl}, and every generator populates it.
This is what makes ground-truth detection possible without out-of-band
configuration: the generator records the secret in play for the level
it was configured with, so a detector reads the ground truth from the
very response it is judging --- which keeps scoring correct even when a
suite sweeps levels within one process.

\label{sec:arch:detectors}
Automatic failure detection is the hard part of LLM security testing,
because whether an output constitutes a failure depends on the
deploying organisation's intent rather than on any property of the
text. PwnzzAI admits a sharper question, because its policy is legible
from its source: the system prompts name the exact word that must not
be emitted at each level, the disclosure lab synthesises PII of exactly
specified shapes, and each seeded account owns an unguessable routing
flag in an isolated database. Every such constant is transcribed into
one module and re-verified against the pinned source by contract tests.
Twelve detectors (Table~\ref{tab:detectors}) therefore test a
\emph{specific policy violation against ground truth} rather than a
stylistic signature~\cite{pwnzzdocsmeth}.

Two refinements are the substance of the architectural claim.
\emph{Obfuscation-aware leak detection:} at the two output-filter
stages the application string-replaces the exact secret on the way out,
so a detector matching only the literal string would score a complying
model as clean. \code{CouponLeak} therefore also matches leetspeak,
separator-injected, and whitespace-stripped forms, and records
\emph{which} rendering matched, so the analysis can distinguish ``the
model said the word'' from ``the model routed around the filter''.
\emph{Abstention over false assurance:} every detector returns
\code{None}, never $0.0$, when it cannot judge --- as a rule whenever
there is no output, and additionally when \code{CouponLeak} finds no
secret in the notes, when \code{Sentiment\bk Label\bk Flip} has no
fitted control model, when the QR round-trip status is unknown, or when
the judge is unreachable or returns \code{ambiguous}. Scoring $0.0$ for
\code{CouponLeak} with no secret in the notes would assert ``no leak''
on evidence that says nothing at all. Combined with the generator-side
rule, the denominator of every reported rate contains only attempts
actually evaluated.

\subsection{An LLM-as-a-Judge as an Opt-In Second Opinion}
\label{sec:arch:judge}

Ground-truth detection has one blind spot: a response can satisfy the
attacker's goal \emph{without matching the pattern} --- a paraphrase, a
hint that gives the coupon away without saying it, a refusal that leaks
while declining. \code{CouponLeak} scores all of those $0.0$, correctly
by its own definition and wrongly by the attacker's. A judge model
registered as an ordinary Garak detector closes that gap, so judged
runs produce the same artefacts as every other run. It is deliberately
constrained: \textbf{off by default}, since it costs a model call per
generation and can be wrong; \textbf{never primary}, because its value
is the \emph{disagreement} with the ground-truth verdict rather than
its raw counts; driven by \textbf{per-scenario criteria}, since asked
the generic question a small judge grades on tone and reads a polite
refusal as failure; and \textbf{abstaining rather than scoring $0.0$}.
The judge is itself a target --- it reads attacker-controlled text from
what is a prompt-injection corpus by construction, the exposure
Greshake et al.\ describe one step further down the
pipeline~\cite[Sec.~3]{greshake2023} --- so its system prompt states
that an embedded instruction is \emph{evidence of a successful attack}
rather than something to obey, and every untrusted field is fenced in a
named delimiter; neither is sufficient alone.

One design decision was measured rather than assumed, and it is why a
1B judge is usable at all. Small judges fail silently: they answer the
same label to everything and invent reasoning to match. Asked for
\code{\{verdict, reasoning\}}, \code{llama3.2:1b} returned ``success''
for plain refusals, with reasoning claiming the response revealed the
coupon word in plain text. Because Ollama's constrained decoding
follows the schema's property order, making the verdict the model's
\emph{last} field forces it to copy a verbatim span out of the response
\emph{before} it reasons or decides --- and it cannot quote a coupon
word from a refusal. Graded against the ground-truth detectors on a
stratified 46-attempt sample of the study's own attempts, the
\code{\{verdict, reasoning\}} order gives $\hi{50\,\%}$ agreement,
$\hi{17}$ false alarms out of roughly 24 non-hits, and $6$ of $26$
\code{success} verdicts whose quoted span does not appear in the
response; \code{\{reasoning, verdict\}} gives $57\,\%$ and $12$; the
shipped \code{\{quoted\_\bk evidence, reasoning, verdict\}} order gives
$\lo{65}$--$\lo{68\,\%}$, $\lo{3}$ false alarms and $\lo{0}$ of $12$
fabricated quotes, the range being run-to-run spread at temperature
$0$. The retained span makes a judge hit auditable.

The resulting judge is high-precision and low-recall: about $75\,\%$ of
what it calls a success is real, and it misses roughly half the real
hits. For a second opinion that is the useful profile, but it does not
support quoting the judge's own attack success rate as a headline
number, and this study does not. Two further guards are reported rather
than assumed: the judge defaults to the model the lab already pulled,
so it shares weights with the model under assessment, a known
soft-grading bias recorded in the run manifest; and a judge returning
one label for $\ge 95\,\%$ of attempts is flagged unusable rather than
having its counts reported. Because it is opt-in and calibrated only
against a 1B grader, no number elsewhere in this paper depends on it.

Three surfaces also ship their own leak flag --- \code{has\_leakage} on
the comment RAG, \code{has\_\bk access\_\bk violation} on the order
assistant, \code{unsafe\_\bk hint\_\bk in\_\bk answer} on the catering
RAG --- and none scores anything. They travel in the notes, and the
analysis layer cross-tabulates them against the independent detector
attempt by attempt: agreement corroborates a finding, and disagreement
is itself a reported result about whether an application-supplied
signal can be trusted. That layer aggregates \code{report.jsonl} but
never re-judges an outcome, so all pass/fail/none counts originate from
Garak's own evaluation entries and every derived table regenerates from
the retained raw artefacts.
